# Repositorios

Inventario de los repositorios de VIVLA que están en producción, agrupados por dominio. Esta wiki es la fuente de verdad técnica de todos ellos.

<Note>
  **Cómo se documenta cada repo.** Hay dos modelos:

  - **Subrepo:** el repo tiene su carpeta `docs/wiki` con su `docs.json`. El workflow `aggregate.yml` de este repo la copia a la wiki.
  - **Agente:** un agente de `vivla-smurfs` lee el código cada día y escribe las páginas directamente en este repo.

  Los repos marcados «Sin documentar» se cubren en la fase 3 del plan de cobertura.
</Note>

## Producto

### vivla-tools

| | |
|---|---|
| **Propósito** | Plataforma interna de VIVLA y corazón operativo del negocio: chat de soporte, encuestas, notificaciones, equipos y permisos, proveedores y facturas, Vivla Identity. |
| **Stack** | Monorepo Turborepo + pnpm. TanStack Start (frontend), NestJS 10 (backend), Supabase (PostgreSQL), Auth0, Stream Chat, Windmill. |
| **Apps** | `backend`, `frontend`, `identity`, `mobile` (app CX), `community-frontend`, `home-excellence`, `owner-portal`, `spark`, `web`, `windmill`, entre otras. |
| **Hosting** | Backend e Identity en Railway, frontend en Vercel. `develop` despliega el entorno de desarrollo y `main` producción (`.github/workflows/deploy.yml`). |
| **Wiki** | Subrepo (`docs/wiki`). El deploy de `main` avisa a la wiki. El agente Editor abre cada mañana un PR que la actualiza. |

### vivla-api

| | |
|---|---|
| **Propósito** | API principal. Sirve a la app de propietarios, al panel de CX y a Tools: reservas, calendarios, casas, invitaciones, usuarios. |
| **Stack** | NestJS 11, PostgreSQL (TypeORM), Firebase/Firestore (datos heredados), Google Cloud Storage. |
| **Hosting** | Railway: `production` desde `master` y `staging` desde `stage`. `develop` es la rama de integración y no se despliega. |
| **Wiki** | El repo no tiene carpeta `docs/wiki`. El agente Scribe lee el código de producción cada mañana y escribe las pestañas [Vivla API](/backend/index) y [Operativa](/operativa/index) directamente en este repo. |

### vivla-mobile-app

| | |
|---|---|
| **Propósito** | App de propietarios: reservar estancias, chatear con CX, gestionar perfil y casas. |
| **Stack** | React Native 0.81, Expo SDK 54, Expo Router, TypeScript, Zustand + React Query, Stream Chat, PostHog, Sentry. |
| **Hosting** | App Store y Google Play con EAS. `develop` publica builds de preview y `main` lanza el pipeline de producción (`.github/workflows/main.yml`). |
| **Conexiones** | vivla-api (auth, reservas, casas, estancias) y Tools API (chat, encuestas). |
| **Wiki** | Subrepo (`docs/wiki`). El pipeline de `main` avisa a la wiki. El agente Editor abre cada mañana un PR que la actualiza. |

### vivla-panel

| | |
|---|---|
| **Propósito** | Backoffice para los agentes de CX. |
| **Stack** | SPA de Vite + React, función serverless para los reportes. |
| **Hosting** | Vercel. El código entra por `staging` y llega a producción con un PR de `staging` a `main`. |
| **Conexiones** | vivla-api. |
| **Wiki** | Subrepo (`docs/wiki`), escrito a mano por el equipo del panel. Llega a la wiki con la ejecución programada de `aggregate.yml`. |

### vivla-cms

| | |
|---|---|
| **Propósito** | Web pública de VIVLA (`www.vivla.com`) y el CMS que la alimenta. |
| **Stack** | Payload CMS + Next.js, PostgreSQL. |
| **Hosting** | Vercel y Railway. |
| **Wiki** | Sin documentar. La fuente es el propio repo. |

## Alma y agentes

### vivla-concierge

| | |
|---|---|
| **Propósito** | Plano de control de los agentes de Alma (Mastra). Aquí vive Lola, la agente de atención a propietarios. |

### vivla-atlas

| | |
|---|---|

| **Hosting** | Railway, servicio `atlas-server` (`mcp.atlas.vivla.com`). No tiene despliegue automático: se publica con `railway up` y el vault viaja dentro de la imagen. |

## Documentación

### docs

| | |
|---|---|
| **Propósito** | Esta wiki: la documentación técnica centralizada de VIVLA. |
| **Stack** | Contenido en MDX con la sintaxis de componentes de Mintlify y `docs.json`. Sitio construido con Astro Starlight. Un Cloudflare Worker sirve el sitio y el servidor MCP. |
| **Hosting** | Cloudflare Workers (`wiki.vivla.com`), detrás de Cloudflare Access con login de Vivla Identity. Staging en `wiki-next.vivla.com`. |
| **Actualización** | `aggregate.yml` copia los subrepos y despliega. Se lanza con cada push a `main`, con el aviso de Tools y de la app, y con una ejecución programada. |
