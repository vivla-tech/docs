Arranca la CLI como servidor MCP por stdio, para que Claude Code, Cursor o Codex la usen como tools: montar repos, ver qué hay desplegado, leer logs o consultar Supabase. No se lanza a mano: lo arranca el cliente.

```bash
claude mcp add --scope user vivla-cli -- npx -y github:vivla-tech/vivla-cli mcp
vivla setup machine --only agents:tooling    # lo mismo, en Claude Code, Cursor y Codex
```

## Cómo funciona

Expone un servidor llamado `vivla` con instrucciones para el agente: empezar por `doctor`, hacer login con `login_start` y `login_poll` si hace falta, y qué hacer con cada `next_actions`. Cada tool abre su propia sesión, como un comando de la CLI.

`setup` y `env_pull` devuelven un `run_id` al momento y siguen en segundo plano; `get_run` hace long-poll de hasta 120 s. Los runs viven en la memoria del proceso del servidor: si el cliente lo reinicia, ese `run_id` deja de existir.

`agents:tooling` (parte de `setup machine`) lo registra como `vivla-cli` con `npx -y github:vivla-tech/vivla-cli mcp`, así siempre corre lo último de `main`:

| Cliente     | Dónde                                                    |
| ----------- | -------------------------------------------------------- |
| Claude Code | `claude mcp add --scope user` (para todos los proyectos) |
| Cursor      | `~/.cursor/mcp.json`                                     |
| Codex       | `~/.codex/config.toml`                                   |

Si encuentra el nombre antiguo (`vivla-welcome`) lo sustituye. [`doctor`](/cli/commands/doctor) comprueba que el servidor conecta en Claude Code.

## Qué toca

Lo que toque cada tool. El servidor en sí solo lee stdin y escribe stdout.

## Salida `--json`

No aplica: habla MCP (JSON-RPC) por stdio. Cada tool devuelve su resultado como texto JSON y como `structuredContent`.

## Exit codes

El proceso vive mientras el cliente lo tenga abierto.

## Para agentes (MCP)

Es este. Las tools están en la tabla de arriba y en [agents.md](/cli/agents#mcp).
