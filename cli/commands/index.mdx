Cada comando tiene su página en esta carpeta: qué hace, ejemplos, opciones, cómo funciona por dentro, qué toca, su salida `--json`, sus exit codes y su tool MCP. Las guías ([montar el entorno](/cli/setup), [día a día](/cli/devtools)) cuentan cómo encajan. `vivla <comando> --help` da las opciones en inglés, y `vivla describe` en JSON.

## De un vistazo

## Opciones globales

Van antes o después del comando y valen para todos.

| Opción                             | Qué hace                                                                                                             |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `--json`                           | salida para máquinas: NDJSON en los runs, un objeto en el resto. Nunca pregunta                                      |
| `--no-interactive`                 | no pregunta nunca; si falta una respuesta, `exit 3`. Por defecto sin TTY                                             |
| `-y`, `--yes`                      | acepta lo que tenga valor por defecto y confirma lo que escribe fuera de tu máquina                                  |
| `--root <dir>`                     | dónde están los clones solo esta vez (si no, la guardada con [`config root`](/cli/commands/config), `VIVLA_CLI_ROOT` o `~/dev`) |
| `--set <clave=valor>`              | responde una pregunta por su clave (repetible): `--set git.name="Ana Pérez"`                                         |
| `--answers <fichero>`              | las respuestas en un JSON: `{ "git.email": "…" }`                                                                    |
| `--git-name`, `--git-email`        | atajos de `--set git.name=…` y `--set git.email=…`                                                                   |
| `--dry-run`                        | solo comprueba, no cambia nada                                                                                       |
| `--force-env`                      | lo que llega de Vercel o Railway sobrescribe tus valores de `.env`                                                   |
| `--connect <remote\|local>`        | los servicios que usa un repo, en staging (por defecto) o en clones locales                                          |
| `--manifest <dir>`                 | usa un catálogo local en vez del de `main` (o `VIVLA_CLI_MANIFEST`)                                                  |
| `--identity-url <url>`             | otra Vivla Identity (o `VIVLA_IDENTITY_URL`)                                                                         |
| `-V`, `--version` · `-h`, `--help` |                                                                                                                      |

Exit codes: `0` ok · `1` falló algo (log en `~/.vivla/cli/vivla.log`) · `2` sin sesión · `3` falta una respuesta · `4` necesita a una persona · `64` argumentos inválidos. Detalle en [agents.md](/cli/agents#exit-codes).
