**Concierge** (`vivla-concierge`) es el plano de control de los agentes de **Alma**: convierte "tenemos una clave de Anthropic y un backend" en "corremos agentes versionados, con trazas, evals, identidad de herramienta con alcance y memoria conectable". Cada agente es un «inquilino» del mismo runtime; añadir uno es añadir una carpeta hermana (`README.md:5`, `apps/concierge/src/mastra/index.ts:46`).

El repo está en producción en la rama `main` y corre en Railway. Para su ubicación en el mapa de repos, mira [Repositorios](/repositories) y [Entornos](/environments).

  Propietario: equipo **IA**. Clase: **agente**. El código de la rama de producción (`main`) es la fuente de verdad de esta sección.
</Info>

## Stack

| Pieza | Elección |
|---|---|
| Runtime | **Mastra** (sobre el Vercel AI SDK): agentes + tools + memoria + OTel (`README.md:16`) |
| LLM | **Claude** de Anthropic — Sonnet responde, Haiku enruta/clasifica. El modelo es una variable de entorno (`models.ts:9`) |
| Observabilidad | **Langfuse** vía OpenTelemetry (`observability.ts:11`) |
| Memoria | Memoria integrada de Mastra; almacenamiento LibSQL o Postgres según `MASTRA_DB_URL` (`storage.ts:47`) |
| Identidad | Tokens delegados On-Behalf-Of (OBO) + registro de auditoría por cada tool-call (`packages/identity`) |
| Monorepo | pnpm + Turborepo, Node 22 (`package.json`, `.nvmrc`) |

## Estructura del repo

```
packages/
  contracts/   tipos de costura compartidos (AgentEvent, AgentResponse, ...)
  identity/    emisor de tokens OBO (Auth0) + sink de auditoría + guard de tools
apps/
  concierge/   la app Mastra que corre
    src/mastra/index.ts        el plano de control (agentes, tools, server)
    src/mastra/agents/          lola · fabian · atlas · simon
    src/mastra/mcp/             clientes MCP (vivla-tools, atlas, vivla-docs)
    src/mastra/tools/           registro de tools + guards
    src/mastra/evals/           scorers LLM-judge + dataset
    src/mastra/workflows/       fabian-pass (pase proactivo de CX)
```
